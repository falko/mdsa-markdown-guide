# Sections

## Numbered headings

Write headings without numbers. Clause, subclause and further numbers are
generated by LaTeX. Each clause file, such as `08_Sections.md`, starts with one
level-1 heading (`#`), the clause title; level-2 and level-3 headings start
subclauses:

```markdown
# Object Model

## Object Semantics
```

Do not write `# 5 The Object Model` or `## 5.1 Overview`. The number would
appear twice ("5.1 5.1 Overview"), and it would be wrong as soon as anything
moves.

## Identifiers

Headings need no identifiers. Link to a heading the way GitHub does, with the
anchor GitHub generates from its text: lower case, spaces become hyphens,
punctuation is dropped. "Object Semantics" becomes `#object-semantics`. In the
PDF, the link becomes the section number (see
[Cross-references](11_Cross-references.md#cross-references)).

Figures and tables need no identifiers either. A link to a figure points to its
image file, a link to a table to its caption heading:

###### Table: Link targets
| Element  | Link target                    | Example                      |
|----------|--------------------------------|------------------------------|
| Sections | heading                        | `#object-semantics`          |
| Tables   | caption heading (`###### Table: ...`) | `#table-link-targets` |
| Figures  | image file                     | `Images/build-pipeline.svg`  |

A heading's anchor changes when its text changes. The build then reports the
links that still use the old anchor. Headings with the same text in different
files, such as an "Overview" in every clause, are no problem. Within one file,
GitHub numbers repeated anchors: the second "Overview" is `#overview-1`, the
third `#overview-2`.

## Unnumbered headings {-}

A heading with `{-}` after its text is not numbered. This subclause is an
example. GitHub shows the `{-}`, so use it sparingly.
