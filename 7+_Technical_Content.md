# Markdown in the MDSA Pipeline {#sec:pipeline}

## How Markdown files are built {#sec:how-built}

A specification repository created from the MDSA template contains one file
per clause, such as `1_Scope.tex` or `7+_Technical_Content.tex`. Any of these
files can be replaced by a Markdown file with the same name and the extension
`.md`, e.g. `7+_Technical_Content.md`. The build converts each Markdown file
to LaTeX with Pandoc [@PANDOC] and then includes it in the specification
template, as shown in @fig:build-pipeline.

![Build pipeline for Markdown content](Images/build-pipeline.svg){#fig:build-pipeline width=80%}

Each Markdown file is converted separately, using the Pandoc settings in the
file `omgLaTeX.yaml`. The default settings come from `mdsa-omg-core`. A file
`omgLaTeX.yaml` in the specification repository replaces them.

# Sections {#sec:sections}

## Numbered headings {#sec:numbered-headings}

Write headings without numbers. Clause, subclause and further numbers are
generated by LaTeX. In a clause file such as `7+_Technical_Content.md`, a
level-1 heading (`#`) starts a new clause, and level-2 and level-3 headings
start subclauses:

```markdown
# Object Model {#sec:object-model}

## Object Semantics {#sec:object-semantics}
```

Do not write `# 5 The Object Model` or `## 5.1 Overview`. The number would
appear twice ("5.1 5.1 Overview"), and it would be wrong as soon as anything
moves.

## Identifiers {#sec:identifiers}

Give every heading, figure and table that is referenced an explicit identifier
with a type prefix:

| Prefix | Used for | Example                    |
|--------|----------|----------------------------|
| `sec:` | Sections | `{#sec:object-semantics}`  |
| `fig:` | Figures  | `{#fig:build-pipeline}`    |
| `tbl:` | Tables   | `{#tbl:files}`             |

Table: Identifier prefixes {#tbl:prefixes}

Pandoc also generates an identifier from the heading text automatically, but
it changes whenever the heading text changes. Do not use it for references.

## Unnumbered headings {-}

A heading with `{-}` after its text is not numbered. This subclause is an

# Figures {#sec:figures}

An image that stands alone in its own paragraph becomes a figure. The text in
the square brackets is the caption:

```markdown
![Build pipeline for Markdown content](Images/build-pipeline.svg){#fig:build-pipeline width=80%}
```

Store images as SVG files in the `Images` folder of the repository. Do not
write the caption as a separate bold line below an image with empty brackets
(`![]`): the figure then gets no number, does not appear in the list of
figures, and cannot be referenced.

# Tables {#sec:tables}

## Table captions {#sec:table-captions}

A paragraph that starts with `Table:` directly before or after a table is its
caption. The identifier goes at the end of the caption:

```markdown
| Feature | Syntax |
|---------|--------|
| Figure  | `![Caption](file.svg){#fig:id}` |

Table: Syntax per feature {#tbl:syntax}
```

All captioned tables, such as @tbl:prefixes and @tbl:abbreviations in
Clause 5, are numbered and appear in the list of tables.

# Cross-references {#sec:cross-references}

## Syntax {#sec:crossref-syntax}

Refer to a labelled element with `@` followed by its identifier:

| You write                      | Output                         |
|--------------------------------|--------------------------------|
| `@sec:figures`                 | @sec:figures                   |
| `@fig:build-pipeline`          | @fig:build-pipeline            |
| `@tbl:files`                   | @tbl:files                     |
| `[@tbl:prefixes; @tbl:files]`  | [@tbl:prefixes; @tbl:files]    |
| `@sec:testing` (other file)    | @sec:testing                   |

Table: Cross-reference syntax and output {#tbl:crossref-output}

References work across files: @sec:testing is in `A_Annexes.md`, and
@tbl:abbreviations is in `5_Symbols.md`.

## How cross-references work {#sec:crossref-how}

Pandoc reads `@fig:build-pipeline` as a citation. The filter pandoc-crossref
[@CROSSREF] turns references whose identifier starts with `sec:`, `fig:` or
`tbl:` into the word "Section", "Figure" or "Table" and a LaTeX `\ref`.
LaTeX fills in the number, so references between files work.

# Citations {#sec:citations}

Cite a bibliography entry by its key:

| You write                  | Output                  |
|----------------------------|-------------------------|
| `[@DMN16]`                 | [@DMN16]                |
| `[@DMN16; @SCE10]`         | [@DMN16; @SCE10]        |
| `[@UML251]` (core entry)   | [@UML251]               |
| `[@PANDOC, Section 8]`     | [@PANDOC, Section 8]    |

Table: Citation syntax and output {#tbl:citations}

The keys come from `omg.bib`, `iso.bib` and `w3.bib` in `mdsa-omg-core`, and
from `specification.bib` in this repository. Cited entries appear in
Clause 3. Entries listed with `\addtocategory{normative}{...}` in
`_Specification_AuthorSettings.tex` appear under "Normative References", all
others under "Non-normative References".

# Other Elements {#sec:other-elements}

## Text formatting {#sec:text-formatting}

*Emphasis*, **strong emphasis**, `inline code` and
[links](https://www.omg.org) are written as usual in Markdown. A footnote is
written like this.[^note]

[^note]: Footnotes are numbered automatically.

## Lists {#sec:lists-markdown}

1. Numbered lists
    a. can be nested,
    b. with letters on the second level.
2. Bullet lists:
    - first item
    - second item

## Code listings {#sec:code-listings}

Fenced code blocks become code listings. Use only languages known to the
LaTeX `listings` package, such as `xml`:

```xml
<definitions xmlns="https://www.omg.org/spec/DMN/20240513/MODEL/">
  <decision id="decision1" name="Decision 1"/>
</definitions>
```

# Lists of Figures and Tables {#sec:lists}

The table of contents, the list of figures and the list of tables are
generated from the numbered headings and the captions. Nothing has to be
written in Markdown. Every figure and table with a caption appears in these
lists.
